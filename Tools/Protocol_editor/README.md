# Fantasy 协议编辑器

Python 桌面工具，用表格和表单编辑 `.proto` 中的消息与字段。默认打开项目的 `examples/Config/NetworkProtocol/Outer/OuterMessage.proto`，不需要运行 Unity。

界面参考 VS Code 的深色配色，采用简洁布局：左侧直接显示消息列表，顶部提供菜单和搜索，右侧编辑字段、预览原文和查看导出日志，底部显示文件状态。原文预览带行号和语法着色，消息与字段编辑弹窗使用同一套深色样式。

## 启动

双击本目录的 **`Start.bat`**。

也可以在 PowerShell 中运行：

```powershell
cd D:\TestProjects\GameFantasy\Tools\Protocol_editor
python .\protocol_editor.py
```

使用 Python 3.10 或更高版本，以及 Python 自带的 Tkinter。当前电脑已安装 Python 3.14 和 Tk 9，无需额外安装库。工具记住上次打开的文件，也支持在启动时传入文件路径：

```powershell
python .\protocol_editor.py "D:\TestProjects\GameFantasy\examples\Config\NetworkProtocol\Outer\OuterMessage.proto"
```

## 编辑方法

1. 左侧“消息定义”并排显示协议名称和中文注释，顶部搜索栏可搜索名称、接口或注释。没有注释时显示 `—`，长注释显示摘要；可拖动列标题分隔线或侧栏分隔线调整宽度。选择消息后，右侧查看字段及只读的原文预览。
2. 点击 **新增消息**，填写名称、接口及说明；普通数据结构可将接口留空。
3. 点击 **新增 RPC**，一次创建请求和回复，自动设置 `IRequest,回复名称` 与 `IResponse`。
4. 选中消息，点击 **添加字段**，填写字段名称、类型、编号、集合类型和说明。双击已有字段可以修改。
5. **编辑消息属性** 可修改名称、接口、关联回复、路由类型和序列化类型。
6. **删除字段 / 删除消息** 删除对应内容。工具不会自动重排其余字段的编号。
7. 点击 **检查协议**，检查名称、字段编号和请求回复关联。
8. 点击 **保存并导出** 或按 `Ctrl+S`，先保存协议，再自动生成 C#。弹窗中的“确定”只将修改应用到内存。

可以使用 `Ctrl+Z` 撤销、`Ctrl+Y` 重做、`Ctrl+O` 打开文件、`Ctrl+P` 搜索消息、`Ctrl+B` 显示或隐藏侧栏。文件标签中的圆点表示存在未保存的修改。切换文件或关闭窗口时，如果存在未保存的修改，工具会询问是否保存。

鼠标在 **＋ 消息** 或 **＋ RPC** 按钮上停留片刻，会显示用途、示例和两者区别；移开或点击后提示自动消失。消息用于单条协议定义，RPC 用于需要回复的请求操作，业务处理逻辑仍需在代码中实现。

## 命名前缀与命名提示

新建消息时，可在名称左侧选择前缀，再输入 `LoginMessage` 等名称，下方会实时预览 `C2G_LoginMessage`。普通数据结构可选择 **无前缀**，例如 `PlayerInfo`。名称建议使用英文，每个单词首字母大写；前缀只用于命名，不会自动改变接口或路由。

默认提供 `C2G_`（客户端 → Gate）、`G2C_`（Gate → 客户端）、`C2M_`（客户端 → Map）、`M2C_`（Map → 客户端）。下拉列表同时显示前缀和含义，鼠标停留在某个选项上可查看详细说明。选中后按钮显示前缀，下方保留含义。新建 RPC 的请求和回复也可以分别选择前缀。

打开 **编辑 → 命名前缀设置**，可以新增、编辑或删除前缀，填写 **前缀、简短含义、详细说明（可选）**。前缀必须以英文字母开头、以下划线结尾，例如 `C2Chat_`。点击 **保存设置** 才会写入本目录的 `.naming-prefixes.json`；取消会放弃本次设置修改，下次启动会读取已保存的选项。删除全部自定义选项后仍可使用“无前缀”。

设置只影响新建窗口，不会重命名已有协议；编辑已有消息时仍直接修改完整名称。如果配置文件损坏，工具会暂用默认选项并提示，原配置不会被自动覆盖。

## 支持的 Fantasy 写法

- 普通字段、消息类型字段和 `map<int32,string>` 等字典字段。
- `repeated`、`repeatedList`、`repeatedArray`，以及原文件中的 `optional` / `required` 修饰符。
- `IMessage`、`IRequest`、`IResponse`，Address、Addressable、CustomRoute、Roaming 消息接口。
- 请求回复关联、路由类型，以及 `// Protocol MemoryPack` / `ProtoBuf`。
- 中文说明、`///` 文档注释、字段行尾注释。
- 原有 `// using`、`////` 和字段前的 `#` 代码注入保留。
- 枚举声明及其他未编辑内容原样保留。第一版不提供枚举值编辑。

包含嵌套声明、`oneof`、`reserved` 或单行消息等复杂结构的消息会显示为只读，避免表格编辑丢失结构。它们仍会保留在文件中，可以编辑同文件中其他受支持的消息。原文预览用于检查内容，不支持直接输入。

检查关联时也会读取同目录及其子目录中的其他 `.proto`，所以回复消息可以位于其他文件。重命名会同步更新当前文件内的类型引用和回复关联；如果其他文件正在引用该消息，工具会提示先协调这些引用。被引用的消息不能直接删除；删除一组 RPC 时，先删除请求，再删除回复。

字段编号不能重复，支持范围为 1～536870911，排除保留区间 19000～19999。自定义 C# 类型可直接输入；完整的框架语义和代码编译结果仍由现有导出工具及 Visual Studio 检查。

## 保存和备份

编辑器对选中的声明做局部修改，未修改部分保留原文。UTF-8 BOM 和原文件换行格式也会保留。

保存已存在的文件前，旧内容备份到本目录的 **`.backups`**，文件名包含原文件名和时间。备份使用 `.proto.bak` 后缀，不会被协议导出工具当作协议文件读取。

如果打开的文件随后被 Visual Studio 或其他程序修改，工具会阻止覆盖；可以取消保存、另存为，或重新打开文件。保存使用临时文件加原子替换。未修改的文件直接保存不会重写，也不会重复产生备份。

## 保存后导出 C#

默认启用 **文件 → 保存后自动导出**。按 `Ctrl+S` 或选择“保存”后，编辑器会在后台执行项目已有的 `ProtocolExportTool`，自动切换到 **导出日志** 标签页，显示工具输出和成功 / 失败结果。

顶部 **保存并导出** 按钮始终执行保存和导出；需要暂存时可选择 **文件 → 仅保存**。自动导出开关会记住上次设置。

导出使用 `examples/Tools/ProtocolExportTool/ExporterSettings.json`，会处理配置目录中的全部协议，更新服务端、Unity 客户端生成代码及操作码缓存；控制台客户端使用项目现有的共享生成代码。导出期间可以查看界面，但需要等待完成后再保存或关闭，避免生成器读到一半修改的文件。

保存失败、检查不通过或取消另存为时不会启动导出。导出失败时已保存的协议会保留，日志会显示原因；修正问题后再次点击“保存并导出”即可，即使协议未再次修改也能重试。另存到配置目录以外的文件只保存，日志会提示无法导出。

如果需要手动执行，可运行：

```powershell
cd D:\TestProjects\GameFantasy\examples\Tools\ProtocolExportTool
dotnet .\Fantasy.ProtocolExportTool.dll export --silent
```

然后在服务端和客户端的 Visual Studio 窗口分别生成解决方案。不要直接修改导出生成的 C# 文件。

## 检查与测试

只检查文件，不打开窗口：

```powershell
python .\protocol_editor.py --check
```

在仓库根目录运行回归测试：

```powershell
python -m unittest discover -s Tools/Protocol_editor -p "test_*.py" -v
```

测试覆盖源文件无损读取、消息和字段增删改、请求回复关联、撤销重做、界面操作、备份、外部修改冲突、保存与导出的执行顺序及错误处理，以及用项目真实导出工具导出临时协议副本。测试不会修改项目中的正式协议或生成代码。
